# Submission protocol and score log

Submissions are ammunition: 1/day in phase 1 (the 20-total cap was removed
2026-08-18; the noised leaderboard still can't rank close variants —
CLAUDE.md discipline rule 4). Every leaderboard submission follows this
protocol:

1. **Before submitting** — the candidate must PASS `score.py` locally on all
   three real schemas and have its wall-clock measured. Improvement adoption
   requires the recorded performance bar; the user's subsequent exploration
   policy also permits a preregistered measurement without positive local
   gain, provided clean no-regression and every-vector assembly parity pass.
   Snapshot the exact code into
   `submissions/YYYY-MM-DD-<name>/` (copy of main.py + requirements.txt +
   the local scores).
2. **Record the expectation** — add a row to the log below with the local
   skill numbers BEFORE the leaderboard result comes back.
3. **After the result** — fill in the reported (noised) score and note the
   local-vs-leaderboard gap. A drift in that gap is itself information
   (phase-1 noise is Laplace ε=10, rounded to 0.01 — expect ±0.01–0.02).

## How to read the log

- Numbering matches `docs/log.md` ("packaged as submission #N"); newest first.
- **Date** = the snapshot directory's date. Where the reported result landed on
  a different day, the Notes column says so.
- **Reported LB** — Codabench shows per-instrument scores only when the
  submission becomes the new best; otherwise only Grand is visible, recorded
  here as "0.63, no update". "no update" means ≤ the incumbent, NOT a failure.
- A **FAILED** row consumed no daily slot (standing fact established 2026-09-13).
- Rows #19–#21 are deliberate **probes** (P1/P2/P3): they degrade the score on
  purpose to measure where the remaining loss sits. Their low Grand values are
  the measurement, not a regression.
- Full pre-registration, scorecard and reasoning for each row live in the
  snapshot's own `SCORES.md`; the experiment verdict lives in
  `docs/experiments/E0XX-*.md`.
- Date provenance for #24/#25 (E040's directory is dated after E041's) is
  documented in `docs/phase2-preparation.md` — directory names are kept as
  recorded and are not reconciled here.

E025) plus E041's supervised retrieval, against fourteen flat, failed or probe
readings that closed the capacity, gate-decoding, cross-round-linkage,
evidence-input and base-model axes one by one.
