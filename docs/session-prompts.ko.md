# HSCC 세션 목록과 시작 프롬프트

적용일: 2026-09-25. 공통 지침은 [workflow.md](workflow.md), 현재 상태는
[status.md](status.md). 아래는 새 채팅에 복사할 프롬프트다.
채팅이나 상주 에이전트를 자동 생성하는 설정은 아니다.

## 세션 구성

| ID | 권장 채팅 제목 | 시작 시점 | 받아야 할 결과 |
| --- | --- | --- | --- |
| S0 | HSCC · 운영과 다음 프롬프트 | 처음 시작, 방향 변경, 다음 작업이 불명확할 때 | 우선순위와 다음 세션용 완성 프롬프트 |
| S1 | HSCC · 연구 · 가설 이름 | 가설 검증 또는 검증 체계 수정 | 실험 기록, 판정 범위, 후속 행동 |
| S2 | HSCC · DEV · E번호 | 후보 조립·검증 또는 제출 결과 수령 | ZIP/판독표 또는 실제 결과 기록 |
| S3 | HSCC · TEST · 최종 후보 | 후보 비교, phase-2 검증, 최종화 | 선택 근거와 최종 제출 준비물 |

매일 네 세션을 모두 열지 않는다. 같은 가설의 후속 작업은 같은 채팅에서
이어가도 된다. 새 가설·다른 산출물·과도하게 긴 맥락이면 새 채팅을 사용한다.
S0를 운영과 프롬프트 제작의 기본 채팅으로 두는 것을 권장한다.

같은 작업 폴더에서 여러 채팅에 동시에 수정 작업을 시키지 않는다.
이전 세션 종료 보고 또는 읽기 전용 상태를 확인하고 다음 세션을 시작한다.
시간·비용 한도를 지정하지 않으면 주력 작업 하나와 정당한 예비 작업 최대
하나를 기본 범위로 삼고, 학습 전 계산량 한도를 명시한다.

## S0 — 운영과 다음 프롬프트

```text
SimulacraBench / HSCC 운영 세션을 시작한다.
작업 폴더: C:\Users\USER\Desktop\SimulacraBench
목표: 최종 TEST 우승 가능성을 높이고 DEV를 유의미한 탐색에 활용한다.

CLAUDE.md → docs/status.md → docs/log.md 최신 3개 항목 순서로 읽고,
docs/workflow.md를 적용해줘. 기존 권한과 선호를 다시 묻지 마.

현재 기준 모델, 마지막 판정, 진행 중인 작업과 제출 상태를 확인해줘.
다음에 해결할 결정 하나를 정하고, 서로 다른 가설을 소수 비교해서
주력과 예비 작업을 선택해줘. 약한 아이디어로 개수만 채우지 마.
비교에는 근거·반대 근거·검증 가능 범위·비용·결과별 행동을 포함해줘.

다음에 열 세션 ID와 채팅 제목, 그대로 붙여 넣을 완성 프롬프트를 작성해줘.
프롬프트에는 정확한 파일/기준 커밋, 목적, 허용 범위, 종료 조건,
평가 데이터 접근 제한과 산출물을 넣어줘. 확인하지 않은 값은 만들지 마.
이번 세션에서는 모델 학습이나 제출물 제작까지 자동으로 시작하지 마.
운영 기록과 인계만 갱신하고, 변경했다면 커밋·push까지 완료해줘.
```

선택해서 덧붙일 정보: 작업 가능한 시간, 계산 비용 상한, 제출 예정일,
새 리더보드 결과. 없으면 파일에서 확인하고 불명확한 것은 불명확하다고 기록한다.

## S1 — 연구와 실험

```text
SimulacraBench / HSCC 연구 세션을 시작한다.
작업 폴더: C:\Users\USER\Desktop\SimulacraBench
CLAUDE.md → docs/status.md → docs/log.md 최신 3개 항목을 읽고
docs/workflow.md를 적용해줘. S0 인계가 있으면 그것을 작업 범위로 사용해줘.

인계가 없으면 이번에 판단할 문제, 주력 가설 하나와 예비 작업을 먼저
명시하고 실행해줘. 기존 실험과 무엇이 다른지, 왜 실제 목표 데이터에서
효과가 있을 수 있는지, 어떤 관측이 그 생각을 반박할지 밝혀줘.

본격적인 추정기·후보 구현 전에 사전 등록과 가장 저렴한 결정적 검증을
수행해줘. 그 검증에 필요한 최소한의 감사·Oracle 도구 구현은 허용한다.
Oracle의 데이터·모델·가중치 범위와 한계를 명시하고, 외부 데이터의
실패를 실제 TEST 전체의 불가능으로 확대하지 마. 기존 STOP은 보존해줘.
기술 검증, 탐색 제출 자격, 최종 채택을 별도로 판단해줘.

허용된 시간·자원 안에서 끝까지 수행하고, 주력이 중단되면 정당한
예비 작업이 준비돼 있을 때 이어가줘. 결과를 본 뒤 기준을 낮추거나
유리한 seed를 찾지 마. 결정이 달라지지 않는 진단은 계속 확장하지 마.
산출물·관측 사실·해석·한계·다음 행동을 보고하고 기록·커밋·push해줘.
제출 후보가 생기면 S2용 인계를 작성해줘. 실제 업로드는 하지 마.
```

## S2 — DEV 제출물 준비

```text
SimulacraBench / HSCC DEV 제출물 준비 세션을 시작한다.
작업 폴더: C:\Users\USER\Desktop\SimulacraBench
CLAUDE.md → docs/status.md → docs/log.md 최신 3개 항목을 읽고
docs/workflow.md를 적용해줘. 지정한 E번호 또는 S1 인계 후보를 대상으로 해줘.

후보가 불명확하면 먼저 실제 준비 상태를 확인하고, 임의의 후보나
제출일을 만들지 마. 과학적 근거와 탐색 목적을 확인한 뒤 파일을 동결해줘.
기존 E025 기준 no-regression과 E041 비교, 조립본 parity,
ZIP checker와 공식 score.py 3개 스키마 검증을 수행해줘.
이미 검증된 동일 파일은 근거 없이 다시 학습하지 말고, 변경되거나
오래되어 무효해진 검증만 적절히 갱신해줘.

SCORES.md에 결과별 해석과 다음 행동을 제출 전에 등록해줘.
파일은 submissions/YYYY-MM-DD-E0XX.zip과 같은 이름의 폴더에 저장해줘.
정확한 ZIP 해시, 검증 결과, 예상 대신 근거 있는 판독 시나리오를 보고해줘.
준비 불가라면 막힌 조건과 바로 할 수 있는 후속 작업을 명시해줘.
실제 업로드는 하지 말고, 기록·커밋·push까지 완료해줘.
```

제출 결과를 받으면 같은 S2 채팅에 아래를 보낸다. 대괄호는 사용자 입력이다.

```text
E[번호] 실제 결과: Grand [값], 최고점 갱신 [예/아니오].
공개된 instrument 점수: [값 또는 미공개]. 플랫폼 상태: [성공/실패 및 코드].
가능하면 제출 시각·제출 ID·ZIP 해시: [확인 가능한 정보만].

docs/workflow.md에 따라 원래 사전 판독표와 비교해 기록해줘.
숨겨진 점수나 효과 0을 단정하지 마. DEV 기준 모델과 TEST 후보에 미치는
영향을 별도로 판단하고, 다음 권고 행동 및 필요한 세션 프롬프트를 작성해줘.
승인된 후속 로컬 작업이 이미 있으면 그 범위에서 이어가고,
새 업로드나 근거 없는 추가 학습은 하지 마. 기록·커밋·push해줘.
```

## S3 — TEST 후보 선택과 최종화

```text
SimulacraBench / HSCC TEST 준비 세션을 시작한다.
작업 폴더: C:\Users\USER\Desktop\SimulacraBench
CLAUDE.md → docs/status.md → docs/log.md 최신 3개 항목을 읽고
docs/workflow.md와 docs/phase2-preparation.md를 적용해줘.

DEV 최고점만으로 선택하지 말고, E041·E025 및 실제 자격을 갖춘 후보를
비교해줘. 비교 대상과 선택 기준을 추가 평가 전에 고정해줘.
TRAIN+DEV 재학습 변화, 일반화 근거, 선택·보정의 데이터 누수,
활성 조건, 전체 실행 시간·메모리와 실패 시 대안을 검토해줘.

필요한 phase-2 검증과 제출 파일 parity를 수행하고,
4페이지 method의 코드·실험·외부 자료 공개 내용 및 라이선스 조건을 맞춰줘.
최종화 시 공식 일정과 규정을 재확인하고, 변경 마감 시점과 동결 파일을
기록해줘. 대안 모델도 별도로 보존해줘. 실제 TEST 업로드는 하지 마.
선택 근거·남은 불확실성·정확한 제출 경로/해시를 보고하고 커밋·push해줘.
```

## 세션 종료 시 받아야 하는 인계

- 결정과 근거, 아직 모르는 점.
- 기준 커밋, 변경 파일, 산출물 경로/해시.
- 점수를 확인한 데이터 역할과 다음 세션에서 접근 가능한 역할.
- 실행 중인 작업의 프로세스/로그 또는 실행 중인 작업 없음.
- 다음 세션 ID, 주력 행동 하나, 정당한 예비 행동, 그대로 쓸 프롬프트.

서브에이전트 배치는 사용자가 매번 지정할 필요 없다. 메인 에이전트가
독립 검토의 가치와 비용을 비교해 한정된 작업만 맡기며, 통합 책임은 유지한다.
