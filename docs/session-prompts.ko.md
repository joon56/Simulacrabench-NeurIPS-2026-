# HSCC 세션 목록과 시작 프롬프트

적용일: 2026-09-25. 공통 지침은 [workflow.md](workflow.md), 현재 상태는
[status.md](status.md). 기본 운영은 S0가 하위 에이전트에 직접 작업을 배정하는 방식이다.
아래 양식은 내부 배정에도 사용한다. 별도 채팅 복사는 선택 사항이며 상주 scheduler 설정은 아니다.

역할·진입 조건 개정: **2026-10-26-r7**. 공통 계약은 workflow.md에 있으며,
아래 프롬프트는 그 적용 양식이다. 사용자의 현재 명시적 범위가 우선한다.
짧은 시작 문구나 과거 인계문은 기존 권한을 넓히지 않는다. 매 세션 시작 시
역할·작업 유형·허용 작업·종료 조건을 요약한다. 프롬프트 작성은 실행이 아니다.

Codex 진입 파일은 저장소 루트 AGENTS.md다. 아래 모든 세션에 workflow.md의
읽기 확인 규칙을 적용한다: 실제 읽은 파일·현재 개정·역할·허용/금지를 먼저
밝히고, 기존 세션 기록에 읽은 시각·HEAD·workflow SHA256·도구 읽기 근거를 남긴다.
해시만 계산하고 읽었다고 보고하지 않는다. 쓰기 금지 작업은 채팅에만 남긴다.
이미 열린 채팅은 지침 개정 후 재개 시 현재 파일을 다시 읽는다. 과거 인계문을
새 지침에 맞춰 소급 수정하거나 다른 세션도 읽었다고 추정하지 않는다.

일반 구현 오류는 담당 세션이 원인을 확인하고 최소 수정·영향 검증 후 계속한다.
인자·import·경로·인코딩·SDK 연결 오류마다 S0 인계나 사용자 승인을 요구하지 않는다.
실패 기록과 누적 시간/비용/시도 횟수를 보존하며, 같은 오류를 고친다는 이유로
한도를 초기화하지 않는다. 범위·데이터·모델 정책·권한·상한 변경이 필요하거나
남은 범위에서 해결할 근거가 없을 때 S0로 반환한다. 원격 부작용이 미확정이면
중복 생성/실행을 막고 허용된 상태 조회·정리를 우선한다.
새 인계에 포괄적인 '첫 오류면 세션 종료'를 넣지 않는다. 과학적 STOP과
중단된 보조 프로세스의 수리는 구분한다. 상세 계약은 workflow r7를 따른다.

## 기본 운영 — S0가 직접 조정하는 하위 에이전트

2026-10-26 사용자 지시로 수동 세션 전달을 기본 절차에서 제거했다.
S0는 후보·범위·예산·판독을 관리하고, 승인된 작업을 child에 직접 전달한다.
같은 executor가 승인된 S1과 조건부 S2를 순차 수행할 수 있다. 리뷰어는 읽기 전용,
S3는 별도 승인 범위다. 한 번에 writer 하나·heavy job 하나; root도 예외가 아니다.
새 가설/데이터/예산을 자동 승인하지 않으며 업로드·최종 TEST 선택 등은 사용자 소관이다.
활성 실행 밖의 무기한 백그라운드 운영을 약속하지 않는다.

```text
S0 운영 유지. 현재 승인된 배치의 범위와 누적 예산 안에서 하위 에이전트에
직접 배정하고 결과를 검토해줘. 내가 다른 채팅으로 인계문을 복사할 필요 없이,
미리 승인한 S1→S2 gate와 일반 수리는 내부에서 처리해줘.
현재 control epoch/task ID·쓰기 담당을 확인하고, writer 해제 전에는 다른
writer를 배정하거나 S0가 파일을 수정하지 마. 승인 범위를 바꾸는 결정만
구체적인 근거·새 범위·예산과 함께 이 채팅에서 확인해줘.
```

Root의 child 배정에는 실제 사용자 권한, task ID/epoch, 역할, 입력·출력,
소유권, aggregate budget, 전환 gate, STOP, 완료 증거를 반드시 채운다.
리뷰어에게는 쓰기·실행·추가 위임 금지를 명시한다. Agent의 최종 답변만으로
PASS 처리하지 말고 허용된 실제 산출물·사용량·해제 기록을 확인한다.

| ID | 권장 채팅 제목 | 시작 시점 | 받아야 할 결과 |
| --- | --- | --- | --- |
| S0 | HSCC · 운영과 다음 프롬프트 | 처음 시작, 방향 변경, 다음 작업이 불명확할 때 | 우선순위와 다음 세션용 완성 프롬프트 |
| S1 | HSCC · 연구 · 판단 문제 | 정보 확보·기술 검증·확증 연구·탐색 연구 | 유형에 맞는 근거와 다음 행동; 모델 산출 필수 아님 |
| S2 | HSCC · DEV · E번호 | 후보 조립·검증 또는 제출 결과 수령 | ZIP/판독표 또는 실제 결과 기록 |
| S3 | HSCC · TEST · 최종 후보 | 후보 비교, phase-2 검증, 최종화 | 선택 근거와 최종 제출 준비물 |

매일 네 세션을 모두 열지 않는다. 같은 가설의 후속 작업은 같은 채팅에서
이어가도 된다. 새 가설·다른 산출물·과도하게 긴 맥락이면 새 채팅을 사용한다.
S0를 운영과 프롬프트 제작의 기본 채팅으로 두는 것을 권장한다.
S0에서 준비한 연구·제출물 제작은 승인된 범위로 실행 child에 배정한다.
배치가 S1→조건부 S2를 미리 허용했다면 같은 executor에서 순차 진행한다.
이미 완료된 S1은 재실행하지 않고 다음 미완료 단계부터 시작한다.
단독 S1/S2 인계도 유효하다. 단독 S1 지시만으로 S2 권한을 만들지 않는다.
같은 채팅에서 역할을 바꾸는 것은 사용자가 그 채팅의 실행을 명시한 예외다.

같은 작업 폴더에서 여러 채팅에 동시에 수정 작업을 시키지 않는다.
이전 세션 종료 보고 또는 읽기 전용 상태를 확인하고 다음 세션을 시작한다.
시간·비용 한도를 지정하지 않으면 주력 작업 하나와 정당한 예비 작업 최대
하나를 기본 범위로 삼고, 학습 전 계산량 한도를 명시한다.

S0에서 "계속 진행", "제출할 수 있게 작업"이라는 목표만 주어졌다면 역할은
S0로 유지한다. S1 실행/S2 제작으로 전환하려면 사용자의 해당 범위 지시가
있어야 한다. 이미 구체적으로 허용된 전환은 다시 승인받지 않는다.
commit/push·외부 접근·업로드는 세션 이름으로 허용되지 않는다.

### 짧은 후속 프롬프트를 쓰는 방법

이미 S0로 정한 채팅에서는 "시작하자", "재개 입력을 전부 수행해줘",
"다양한 실험을 진행하자"만으로 역할이 바뀌지 않는다. 사용자가 매번 금지
목록을 붙일 의무는 없다. 에이전트가 S0 범위에서 선정·기록·인계를 완료한다.

기본 운영을 명확히 쓰고 싶다면:

```text
S0 유지. 다음 DEV 후보의 한정된 실행 계약을 작성하고, 이미 승인된 범위는
하위 에이전트에 직접 배정해줘. S0 본체는 문서·검토·조정 역할을 유지해줘.
```

단독 S1만 승인할 때는 S0 인계문을 붙이고 다음 문장을 덧붙인다:

```text
이 채팅은 S1이다. 첨부 인계의 허용 범위만 실행하고 종료 조건에서 멈춰줘.
후보가 준비되면 S2 인계까지 작성하고, 제출물 제작으로 전환하지 마.
```

같은 S0 채팅에서 실제 역할 전환을 원할 때만:

```text
이번에는 이 채팅을 S0에서 S1으로 전환해, 지정한 인계문 범위를 직접 실행해줘.
S2 제작·업로드·commit/push·S3/TEST 선택은 허용하지 않는다.
```

표현이 이 예시와 같아야 하는 것은 아니다. **누가(이 채팅/별도 세션), 무엇을
(검토/구현/학습/제작), 어디까지**인지 명확하면 된다. 에이전트가 작성한
"S1으로 전환하겠다"는 선언이나 인계문 자체는 사용자 지시의 대체물이 아니다.

## S0 — 운영과 다음 프롬프트

```text
SimulacraBench / HSCC 운영 세션을 시작한다.
작업 폴더: C:\Users\USER\Desktop\SimulacraBench
목표: 최종 TEST 우승 가능성을 높이고 DEV를 유의미한 탐색에 활용한다.

CLAUDE.md → docs/status.md → docs/log.md 최신 3개 항목 순서로 읽고,
docs/workflow.md를 적용해줘. 기존 권한과 선호를 다시 묻지 마.
실제 읽은 개정·파일·역할·허용 범위를 먼저 보고하고 읽기 확인 근거를 남겨줘.

현재 기준 모델, 마지막 판정, 진행 중인 작업과 제출 상태를 확인해줘.
다음에 해결할 결정 하나를 정하고, 서로 다른 가설을 소수 비교해서
주력과 예비 작업을 선택해줘. 약한 아이디어로 개수만 채우지 마.
비교에는 근거·반대 근거·검증 가능 범위·비용·결과별 행동을 포함해줘.

정보 확보·기술 검증·확증 연구·탐색 DEV 중 다음 작업 유형을 정해줘.
같은 HOLD를 새 입력 없이 다시 검토하지 마. 부족한 정보가 확보 가능하면
구체적인 출처·담당·허용 접근·비용·결과별 행동이 있는 S1 과제로 바꿔줘.
확보 과제도 정당화되지 않으면 정확한 재개 조건을 남기고 종료해줘.
다음 과제가 구체적일 때 task ID·실행 계약을 작성하고 승인된 범위만 child에 배정해줘.
준비된 후보만 승인 배치에 묶고, S1→조건부 S2 gate·신규 예산·재사용 조건을 미리
명시해줘. 이미 완료된 구현/성공 검증은 다음 배치에서 반복하지 마. S3는 별도 범위다.
프롬프트에는 정확한 파일/기준 커밋, 목적, 허용 범위, 종료 조건,
평가 데이터 접근 제한과 산출물을 넣어줘. 확인하지 않은 값은 만들지 마.
S0는 전략·기록·인계만 수행해줘. 실험 코드·학습·점수 계산·보호 응답 접근·
제출물 제작을 시작하지 마. 현재 지시에서 허용되지 않은 commit/push,
업로드·S3 재개·TEST 선택도 하지 마. 기존 STOP/HOLD와 사용자 변경을 보존해줘.
이 역할은 후속 메시지에도 유지한다. 다른 역할의 실행은 승인된 child에 배정하고,
내가 이 채팅의 역할 전환을 명시하지 않으면 직접 수행하지 마.
```

선택해서 덧붙일 정보: 작업 가능한 시간, 계산 비용 상한, 제출 예정일,
새 리더보드 결과. 없으면 파일에서 확인하고 불명확한 것은 불명확하다고 기록한다.

## 실행 child 또는 선택적 별도 세션 — 승인된 S1·조건부 S2 배치

역사 예시: [B01 E064 release](analysis/A044-outputs/batch-01-e064-release.ko.md)는 완료됐다.
이를 새 실행 지시로 재사용하지 않는다. 현재 배치는 status의 연결 기록을 따른다.
아래 양식의 대괄호는 실제 인계 경로로 바꾼다. 파일 작성만으로 실행되지 않는다.

```text
이 executor에 [정확한 배치 인계 경로]의 이미 승인된 후보·신규 예산·조건부 전환을
배정한다. Root가 전달한 실제 사용자 승인 근거와 task ID/epoch를 확인한다.
AGENTS → CLAUDE → status → log 최신3개 → workflow와
인계문을 실제 읽고, 현재 개정·사용자 승인 근거·쓰기 담당 인수를 기록해줘.
이전 쓰기 담당의 종료/해제와 진행 중 작업을 확인한 뒤 단독으로 수정해줘.

완료된 단계는 식별값/입력/환경/출처가 유효하면 재사용한다. 다음 미완료 단계부터
진행하고, 인계에 고정한 S1→S2 조건을 충족하면 별도 S0 승인 없이 같은 세션에서
역할 전환 근거를 기록하고 진행해줘. 승인에 없는 후보나 단계를 만들지 마.
일반 구현 오류는 실패·소진 예산을 보존하고 최소 수정·영향 검사 후 계속해줘.
성공한 검증·학습을 이유 없이 반복하지 마. 새 가설·데이터·과학적 기준·예산 변경,
한도 소진은 S0로 반환해줘. 업로드·새 유료 자원·서브에이전트·commit/push·S3는 제외한다.
종료 시 산출물·누적 사용량·작업/PID 상태·다음 소유자를 남기고 쓰기 담당을 해제해줘.
```

배치 승인 전 인계에는 후보 목록, 완료 단계, 소스/입력 해시, 허용 파일/산출물,
전체 gross·계산·비용·시도 상한, 단계별 전환 조건, 재사용/무효화 조건,
판독표와 STOP, 소유권 순서가 있어야 한다. 과거 잔여 예산을 신규 예산으로 쓰지 않는다.

## S1 — 정보 확보·검증·연구

```text
실제 읽은 개정·파일·역할·허용 범위를 먼저 보고하고 읽기 확인 근거를 남겨줘.

정보 확보·기술 검증·확증 연구·탐색 DEV 중 인계의 작업 유형을 확인하고,
해당 유형의 진입 조건만 적용해줘. 역할·판단 문제·허용 작업·상한·종료 조건을
먼저 요약해줘. 인계가 없으면 현재 사용자 지시에서 구체적으로 허용된 범위를
정의해줘. S1이라는 이름만으로 fit·평가 자료 접근을 허용하지 마.

정보 확보 과제는 출처·접근 조건·미확정 사실과 다음 행동을 산출해줘.
모델 효과나 완성된 평가 정밀도 계획을 자료 조사 자체의 진입 조건으로
요구하지 마. 공개 문서 열람 허가를 응답 다운로드·이용 허가로 확대하지 마.
기술 검증은 지정된 불변 조건/결함만 검증하고 효과 증거와 구분해줘.
일반 구현 오류는 같은 세션에서 원인 확인·최소 수정·관련 검증 후 계속해줘.
workflow r7에 따라 실패/사용량을 보존하고, 범위나 상한이 바뀔 때만 S0로 반환해줘.

모델 연구가 허용된 경우 기존 실험과의 차이·실제 기제·반대 근거를 명시하고,
추정기 구현 전에 사전 등록과 허용된 가장 저렴한 결정적 검증을 수행해줘.
확증 연구는 독립 역할·추정 대상·정밀도/오차 처리를 먼저 정해줘. 별도 탐색은
새 기제·채널 한계·자원·release 기준·판독 행동을 고정해줘. 유효한 oracle이면
먼저 사용하고, 기제를 평가할 수 없다면 그 이유를 기록해줘. 이를 과거 STOP
우회나 검증 기준 완화에 사용하지 마. 도구 구현도 인계의 허용 범위 안에서 해줘.
Oracle의 데이터·모델·가중치 범위와 한계를 명시하고, 외부 데이터의
실패를 실제 TEST 전체의 불가능으로 확대하지 마. 기존 STOP은 보존해줘.
기술 검증, 탐색 제출 자격, 최종 채택을 별도로 판단해줘.

허용된 시간·자원 안에서 끝까지 수행하고, 주력이 중단되면 정당한
예비 작업이 준비돼 있을 때 이어가줘. 결과를 본 뒤 기준을 낮추거나
유리한 seed를 찾지 마. 결정이 달라지지 않는 진단은 계속 확장하지 마.
산출물·관측 사실·해석·한계·다음 행동을 기록해줘. 모델이 없어도 판단을 바꿀
정보를 얻거나 부적합한 경로를 종료했다면 과제 완료로 보고해줘.
이 단독 S1 범위에서는 후보가 생기면 S2용 인계를 작성하고 ZIP 제작으로 전환하지 마.
사용자가 별도 승인한 배치에 조건부 S2가 명시된 경우에만 그 배치의 전환 조건을 따른다.
commit/push·업로드는 현재 별도 허용 범위가 없다면 수행하지 마.
```

## 세션 종료 시 받아야 하는 인계

- 결정과 근거, 아직 모르는 점.
- 실제 읽은 workflow 개정/SHA256, 읽기 근거와 세션 역할/허용 범위.
- 기준 커밋, 변경 파일, 산출물 경로/해시.
- 점수를 확인한 데이터 역할과 다음 세션에서 접근 가능한 역할.
- 실행 중인 작업의 프로세스/로그 또는 실행 중인 작업 없음.
- 쓰기 담당의 소유 경로·해제 시각과 다음 세션 인수 조건. 한 checkout의 writer는 하나.
- 다음 작업 유형·세션 ID·주력·정당한 예비 행동과 결과별 행동.
- 구체적인 후속 과제가 있을 때만 완성 프롬프트. 없으면 부족한 입력·확보 방법·
  담당·상한·재개 조건. 같은 조건으로 다시 HOLD 문서만 만들지 않음.
- 인계 작성이 허용하지 않는 실행·데이터 접근·역할 전환·git 작업.

서브에이전트 배정은 현재 사용자의 r7 운영 승인과 각 작업의 허용 범위를 따른다.
Root만 배정하며 child의 재위임은 금지한다. 배치 이름만으로 새 실행 권한을 만들지 않는다.
공유 checkout writer는 root 포함 하나이며, S3와 DEV executor가 동시에 수정하지 않는다.
