# A014 SIPP metadata review

Date: 2026-09-24. Scope: independent documentation review. No respondent values, model fits, or scores inspected here. This review establishes a **conditional metadata pass**, not acceptance of the observed channel. Public-file value encoding, counts, and contradictions remain empirical gates.

## Official sources and record grain

- [2023 SIPP PUF Data Dictionary](https://www2.census.gov/programs-surveys/sipp/tech-documentation/data-dictionaries/2023/2023_SIPP_Data_Dictionary.pdf), notes on printed p. 8; hospital block pp. 1134-1142; ID variables pp. 1284-1296; age p. 795; education p. 934; origin p. 936; marital status p. 941; race p. 968; sex p. 971.
- [2023 SIPP Users' Guide, August 2026](https://www2.census.gov/programs-surveys/sipp/tech-documentation/methodology/2023_SIPP_Users_Guide_AUG26.pdf), sections 3.1-3.5 and 4.1.1. Its variable-prefix table identifies `E` as edited survey data, `T` as disclosure-protected variables, and `A` as universe/imputation flags. These are processed public-use values, not guaranteed verbatim interview answers.
- [Official 2023 release and input example](https://www.census.gov/data/datasets/2023/demo/sipp/2023-data.html). The locally cached `input-example.py` says unique person = `SSUID+PNUM`, household at a month = `SSUID+ERESIDENCEID`, and demonstrates selected-column loading. Its schema JSON labels corroborate the dictionary but do not specify response domains or missing encodings.

Primary file has up to twelve **person-month** records per person. Person-level fields are copied to each of that person's month records. Choosing `MONTHCODE=12` and verifying one record per `(SSUID, PNUM, MONTHCODE)` is necessary to avoid same-person duplication across roles. This reference month is a row-selection rule: `THOSPNIT` counts nights during the **reference period**, and the reason items refer to the **most recent stay**, not necessarily month 12. `TAGE_EHC` is monthly age; `TAGE` is age at interview. The age criterion in the `THOSPNIT` universe specifically says `TAGE_EHC(12)>0`, so substituting `TAGE>0` would be inaccurate. [Dictionary, hospital block](https://www2.census.gov/programs-surveys/sipp/tech-documentation/data-dictionaries/2023/2023_SIPP_Data_Dictionary.pdf); [Users' Guide, sections 3.1 and 4.1.1](https://www2.census.gov/programs-surveys/sipp/tech-documentation/methodology/2023_SIPP_Users_Guide_AUG26.pdf).

`SSUID` identifies the original sample unit; `(SSUID,PNUM)` identifies a person. `SHHADID` identifies interview households spawned from a sample unit and can change over the panel. Monthly residence is `(SSUID,ERESIDENCEID)` and can change as a person moves. Thus `(SSUID,SHHADID)` is an interview-household descriptor, not a stable whole-year or unique-person key. Grouping by `SSUID` is conservative for the household-held-out split because it keeps related spawned households together, though it can reduce effective split size. Keep identifiers solely for uniqueness/provenance/splits. [Users' Guide, sections 3.4-3.5](https://www2.census.gov/programs-surveys/sipp/tech-documentation/methodology/2023_SIPP_Users_Guide_AUG26.pdf).

## Eligibility and outputs

`THOSPNIT` asks number of nights in hospital, dictionary range `0..365`. Its universe is `THHLDSTATUS in (1,2)` and `TAGE_EHC(12)>0`: new or returning household members at least one year old by month 12. `THHLDSTATUS=1` means returning and `2` new; statuses 3-6 have other roster meanings. Its status flag is `AHOSPNIT`. Each of `EHREAS_DT`, `EHREAS_BIR`, `EHREAS_OS`, `EHREAS_NST`, `EHREAS_OTH`, `EHREAS_COR` has person-level universe `THOSPNIT>=1`, with values `1=Yes`, `2=No` and shared flag `AHREASON`. The reasons correspond to diagnostic test; birth/giving birth; operation/surgery; nonsurgical treatment/therapy; other reason; and COVID-19 treatment/complications. [Dictionary, pp. 1134-1140](https://www2.census.gov/programs-surveys/sipp/tech-documentation/data-dictionaries/2023/2023_SIPP_Data_Dictionary.pdf).

**Metadata pass:** a single parent `THOSPNIT` coarsened to `0` versus `>=1` preserves the documented gate for all six child indicators. This is a legitimate one-parent, six-child coupled routing problem. The coarsening discards duration information and should be disclosed. The six reasons are separate binary indicators; do not force exactly one `Yes`, assume at least one `Yes`, or fill missing reasons from other answers. A parent value that is missing or outside `0..365` is ambiguous until public encoding and flags establish its meaning. If all eligible outcomes cannot be encoded without inventing a nonresponse level or gate sentinel, reject the mapping. Out-of-universe values must be mapped only after checking the public file and `AHREASON=0`, with all parent-child disagreements reported. This is an inference from the documented universes, subject to data audit.

## Missing values, imputation, and leakage

The dictionary's `.N` numeric / `N` character not-in-universe code is **explicitly for internal SIPP data**. It does not establish public CSV encoding. The guide defines status flag `0=not in universe`, `1=reported`, `2..6` as imputation types, `7..8` as combinations, and `9` as component-flag interpretation for recodes. A public blank/NA, zero, or other value must be characterized by an observed cross-tab with `AHOSPNIT` and `AHREASON`, separately for parent and six children. An in-universe missing response must not be rewritten as not-in-universe merely to make the gate exact. Keep imputed outputs and report flag counts; selecting only flag 1 would bias the channel. [Dictionary, notes p. 8](https://www2.census.gov/programs-surveys/sipp/tech-documentation/data-dictionaries/2023/2023_SIPP_Data_Dictionary.pdf); [Users' Guide, section 3.3](https://www2.census.gov/programs-surveys/sipp/tech-documentation/methodology/2023_SIPP_Users_Guide_AUG26.pdf).

`AHOSPNIT` and `AHREASON` encode universe and processing status, so they are audit-only fields, never GIVEN inputs. `THOSPNIT_MED` and `_STD` describe topcoded values; exclude them. Exclude hospital/health summaries, target recodes, household copies, and IDs. The six proposed demographic inputs are person-level basic demographics, not direct hospital-target copies by their documented definitions. Their public values can still be edited or imputed; that is a measured-data limitation, not proof of leakage. The Users' Guide also warns that public-use files may be topcoded, perturbed, or suppressed. [Users' Guide, sections 3.1-3.3, 4.1.1](https://www2.census.gov/programs-surveys/sipp/tech-documentation/methodology/2023_SIPP_Users_Guide_AUG26.pdf); [Dictionary, hospital block](https://www2.census.gov/programs-surveys/sipp/tech-documentation/data-dictionaries/2023/2023_SIPP_Data_Dictionary.pdf).

## Proposed GIVEN fields

| Field | Dictionary meaning and universe | Decision/risk |
| --- | --- | --- |
| `TAGE` | Age at last birthday **at interview**; all persons; public range `0..90`. | Candidate input, distinct from month-12 eligibility age. Age may be topcoded. |
| `ESEX` | Sex, male/female; all persons. | Candidate input. |
| `ERACE` | Broad race categories: White alone, Black alone, Asian alone, residual; all persons. | Candidate input; public grouping is coarse. |
| `EORIGIN` | Hispanic/Latino/Spanish origin yes/no; all persons. | Candidate input. |
| `EEDUC` | Highest schooling/degree by December of reference year; `TAGE>=15`. | Candidate only with genuine under-15 not-in-universe preserved as feature missing/category, not treated as respondent nonresponse. |
| `EMS` | Current marital status at interview; `TAGE>=15` **and** `THHLDSTATUS in (1,2)`. | Candidate only with same universe treatment. In primary eligible population, the household-status condition already holds; age condition remains. |

Dictionary entries: [age](https://www2.census.gov/programs-surveys/sipp/tech-documentation/data-dictionaries/2023/2023_SIPP_Data_Dictionary.pdf), [education](https://www2.census.gov/programs-surveys/sipp/tech-documentation/data-dictionaries/2023/2023_SIPP_Data_Dictionary.pdf), [marital status](https://www2.census.gov/programs-surveys/sipp/tech-documentation/data-dictionaries/2023/2023_SIPP_Data_Dictionary.pdf), and [race/sex](https://www2.census.gov/programs-surveys/sipp/tech-documentation/data-dictionaries/2023/2023_SIPP_Data_Dictionary.pdf). Four fields are all-age candidates on metadata; the other two need missingness handling and observed usability checks. The gate's `>=4` usable-input condition is **not proven by metadata alone**.

## Decisions for integration

- **Pass, documentation only:** exact `THOSPNIT>=1` child universe; one common person-level parent; six person-level yes/no reason fields; identified month-12 eligibility field; independent demographic candidates; key semantics support one-row-per-person and conservative `SSUID` grouping.
- **Block acceptance until data audit:** public missing encoding versus flag 0; whether every eligible parent and child output is encodable; duplicate `(SSUID,PNUM,MONTHCODE)` and repeated-person checks; parent-child contradiction counts; status-flag distribution and input missingness; >=5,000 eligible persons, >=200 hospitalized persons, >=4 usable GIVEN fields. Report all contradictions and do not drop cases to obtain a clean gate.
- **Interpretation limit after any pass:** edited/imputed and disclosure-protected US health-survey data give an observed routing proxy. They do not validate UNHCR gate agreement, target-population similarity, calibration headroom, or DEV-score gain. Model selection still requires the preregistered independent splits and scoped oracle in the A014 plan.
